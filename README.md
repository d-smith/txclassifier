# Transaction Classifier

A supervised ML pipeline that classifies personal finance transactions
(`description`, `amount`, `date`) into a fixed taxonomy of **14 categories /
71 subcategories**. Built as a learning project covering the full path from
preprocessing through training to a served FastAPI model, with an explicit
design goal of **zero train/serve skew** and a clean seam for swapping the
sklearn baseline for a transformer model later.

See `starting-prompt.md` for the original requirements and taxonomy, and
`ultraplan.md` for the full design writeup this implementation follows.

## How it works

**No-skew mechanism.** Exactly one `ColumnTransformer` (`src/features.py:
build_preprocessor()`) is fit once, in `src/train.py`, and persisted to
`models/preprocessor.joblib`. Every other consumer — the 14 subcategory
training loops, `src/evaluate.py`, and `SklearnPredictor` at serve time —
loads that fitted object and only ever calls `.transform()` on it. There is
no second `ColumnTransformer` construction anywhere in the codebase, which
rules out train/serve skew by construction rather than by convention.

**Two-level classification.** One category `LogisticRegression` model, plus
one independently-trained subcategory `LogisticRegression` model per
category (14 total). At inference time the category model predicts first;
its predicted category selects which subcategory model to route to.
Confidence is reported as `P(category) * P(subcategory | predicted
category)` — a reasonable but not rigorously calibrated joint probability.

**Features** (`src/features.py`): TF-IDF char n-grams (`analyzer="char_wb"`,
`ngram_range=(3,5)`) on `description`; median-imputed + standard-scaled
`amount`; one-hot-encoded day-of-week, derived *inside* the pipeline from
`date` by a custom `DayOfWeekExtractor` transformer (not computed separately
by train/serve call sites).

**Label hygiene** (`src/data_loader.py`): rows with a missing/blank
`category` or `subcategory` are dropped entirely before training —
`drop_unlabeled()` is the only thing that touches label cleanliness for
training purposes. `"Unknown"` is never a class the model learns to predict;
it's a reporting-only label for blank raw input, produced by the separate
`label_or_unknown()` helper.

**Predictor abstraction** (`src/predictor.py`): `serve/main.py` depends only
on the `Predictor` Protocol (`predict(description, amount, date) ->
PredictionResult`, `health_check()`), implemented today by
`SklearnPredictor`. A future `TransformerPredictor` implementing the same
contract can swap in with a one-line change in `serve/main.py`'s startup, with
no endpoint or schema changes.

## Setup

Environment management uses [`uv`](https://docs.astral.sh/uv/) instead of
raw `pip`/`venv`. Every command below is run with `uv run` so it executes
inside `.venv` without a manual `source .venv/bin/activate` step.

```bash
uv venv                              # create .venv
uv pip install -r requirements.txt   # install pandas, scikit-learn, fastapi, uvicorn, pydantic, joblib, numpy
```

Run all commands from the repo root, so the `src`/`serve` package imports
resolve without needing an install step.

## Milestone-by-milestone verification

These mirror the build order in `ultraplan.md`. Run them in order the first
time; after that, `uv run python -m src.train` (M4) is the one command you
need to regenerate everything under `models/`.

### M0 — Taxonomy self-check

Confirms the taxonomy is exactly 14 categories / 71 subcategories.

```bash
uv run python -c "from src import taxonomy; print(len(taxonomy.CATEGORIES), sum(len(v) for v in taxonomy.CATEGORIES.values()))"
```

Expected output: `14 71`

### M1 — Generate synthetic data

```bash
uv run python -m src.synthetic_data
```

Writes `data/synthetic/synthetic_transactions.csv`. Inspect it:

```bash
uv run python -c "
import pandas as pd
df = pd.read_csv('data/synthetic/synthetic_transactions.csv')
print(df.shape)
print(df.sample(10))
print(df['category'].value_counts())
print(df['category'].eq('').sum(), 'blank category rows')
print(df['subcategory'].eq('').sum(), 'blank subcategory rows')
"
```

Confirm: columns are `date, description, amount, category, subcategory`,
class counts are roughly even (~30 rows/subcategory), and there are a
handful (~20-30) of injected blank-label rows.

### M2 — Drop-report sanity check

Confirms `drop_unlabeled()` catches exactly the injected blank-label rows.

```bash
uv run python -c "
from src import data_loader, config
df = data_loader.load_raw_transactions(config.SYNTHETIC_DATA_PATH)
clean_df, report = data_loader.drop_unlabeled(df)
print(report)
"
```

### M3 — Preprocessor sanity-transform

Fits the preprocessor on a small sample and checks the output shape has no
NaNs and includes 7 one-hot day-of-week columns.

```bash
uv run python -c "
from src import data_loader, config, features
df = data_loader.load_raw_transactions(config.SYNTHETIC_DATA_PATH)
clean_df, _ = data_loader.drop_unlabeled(df)
sample = clean_df.sample(20, random_state=0)
pre = features.build_preprocessor()
X = pre.fit_transform(sample)
print(X.shape)
import numpy as np
print('has NaN:', np.isnan(X.toarray()).any() if hasattr(X, 'toarray') else np.isnan(X).any())
"
```

### M4 — Train all models

Trains the category model and all 14 subcategory models, and writes every
artifact under `models/`.

```bash
uv run python -m src.train
```

Eyeball the printed drop report, per-class precision/recall, and confusion
matrices for mostly-diagonal structure. Then confirm the artifacts exist:

```bash
find models -type f | sort
```

Expected: `preprocessor.joblib`, `category_model.joblib`,
`category_label_encoder.joblib`, 28 files under `subcategory_models/` (14
models + 14 encoders), `metrics/category.json` + 14
`metrics/subcategory_<slug>.json` files, and `metadata.json`.

### M5 — Manual prediction gate (pre-FastAPI sanity check)

Run the built-in hand-picked examples spanning several categories:

```bash
uv run python -m src.predict_cli
```

Or test a single example directly:

```bash
uv run python -m src.predict_cli "STARBUCKS #4521" 5.75 2025-06-10
```

Expect something like `Food & Dining / Coffee shops` with a high confidence
score. Confirm predictions are sane across categories before moving on to
the API.

### M6 — Iterate and re-evaluate

After any tweaks to `src/features.py` or model hyperparameters in
`src/train.py`, retrain and diff metrics:

```bash
uv run python -m src.train
```

Compare `models/metrics/*.json` against a previous run (e.g. `git diff` if
committed, or a saved copy) and check confusion-matrix off-diagonals for
systematic confusions (e.g. Fast food vs. Dining out).

### M7 — Start and verify the FastAPI server

Start the API (requires `models/` to already exist from M4):

```bash
uv run uvicorn serve.main:app --reload --port 8000
```

In another terminal, verify health:

```bash
curl -s http://localhost:8000/health | jq
```

Expected: `{"status": "ok", "model_loaded": true}`

Verify a prediction:

```bash
curl -s -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"description": "STARBUCKS #4521", "amount": 5.75, "date": "2025-06-10"}' \
  | jq
```

Expected response shape (exact confidence values will vary run-to-run since
training does a random 80/20 split, but category/subcategory should match):

```json
{
  "category": "Food & Dining",
  "subcategory": "Coffee shops",
  "confidence": 0.22,
  "category_confidence": 0.52,
  "subcategory_confidence": 0.42
}
```

Confidence scores on this synthetic dataset are fairly low in absolute terms
(the TF-IDF + LogisticRegression baseline isn't near-certain on short,
similar-looking merchant strings) — the top-level category/subcategory
predictions are what to sanity-check here, not the raw probability.

Try a few more spanning different categories:

```bash
curl -s -X POST http://localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"description": "CHASE MORTGAGE PYMT", "amount": 1850.00, "date": "2025-02-01"}' | jq

curl -s -X POST http://localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"description": "UBER TRIP", "amount": 12.40, "date": "2025-04-18"}' | jq

curl -s -X POST http://localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"description": "PETSMART #55", "amount": 38.20, "date": "2025-03-29"}' | jq
```

Browse the interactive OpenAPI docs at `http://localhost:8000/docs`.

Stop the server with `Ctrl+C` when done.

### M8 — Point at real data (later, separate session)

Once real labeled data is available as `data/raw/transactions.csv` (columns:
`date, description, amount, category, subcategory`), you can either train on
it exclusively:

```bash
uv run python -m src.train data/raw/transactions.csv
```

(or permanently repoint `src/config.py`'s `TRAINING_DATA_PATH` from
`SYNTHETIC_DATA_PATH` to `RAW_DATA_PATH` and run `uv run python -m src.train`
with no arguments), or combine it with the synthetic data first — see
[Training on synthetic + your own labeled data](#training-on-synthetic--your-own-labeled-data)
below.

Any real subcategory with too few rows to stratify-split will trigger a
warning and an unstratified split fallback (see `_stratified_split` in
`src/train.py`) — treat that as a signal to review label volume for that
subcategory, not a bug to silence.

## Docker

The `Dockerfile` packages `serve/main.py` (and its `src/` dependency) into an
image. Model artifacts under `models/` are **not** baked into the image —
they're generated separately by `uv run python -m src.train` and mounted in
at container run time. This keeps the image lean and means you don't have to
rebuild it every time you retrain; if you'd rather have a fully
self-contained image for an actual deployment, add a `COPY models/ models/`
line to the `Dockerfile` and drop the volume mount below.

### Build

```bash
docker build -t txclassifier:latest .
```

### Run (models mounted read-only from the host)

Make sure `models/` already exists (run M4's `uv run python -m src.train`
first if not), then:

```bash
docker run -d --name txclassifier \
  -p 8000:8000 \
  -v "$(pwd)/models:/app/models:ro" \
  txclassifier:latest
```

The container listens on `8000` internally (`uvicorn --host 0.0.0.0 --port
8000` in the `Dockerfile`'s `CMD`); `-p 8000:8000` maps that to the same
port on the host — change the host-side number if `8000` is already in use
locally.

### Verify

Give it a couple seconds to finish loading the model artifacts, then run the
same health/predict checks as M7:

```bash
curl -s http://localhost:8000/health

curl -s -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"description": "STARBUCKS #4521", "amount": 5.75, "date": "2025-06-10"}'
```

Expected: `{"status":"ok","model_loaded":true}` from `/health`, and a
category/subcategory prediction from `/predict` matching what `predict_cli`
gave you in M5.

Tail logs or stop the container when done:

```bash
docker logs -f txclassifier
docker rm -f txclassifier
```

### Retraining

Since `models/` is a mounted volume rather than baked into the image, picking
up a new model after retraining (M6, or after adding your own labeled data)
just means retraining on the host and restarting the container — no rebuild
needed:

```bash
uv run python -m src.train
docker restart txclassifier
```

### Notes on the image

- `.dockerignore` excludes `.venv`, `data/`, `models/`, `.git`, and `*.md`
  from the build context — none of those are needed to run the API, and
  `models/` is supplied at runtime instead.
- The `Dockerfile` installs dependencies with `uv pip install --system` (uv
  installed via `pip` inside the image) rather than `uv run`, since the
  container *is* the isolated environment — there's no `.venv` to route
  through.
- `serve/main.py`'s `lifespan` loads `SklearnPredictor` once at container
  startup, exactly like it does when run directly with `uv run uvicorn`; if
  `models/` isn't mounted (or a training run left it incomplete), startup
  will throw and the container will exit — check `docker logs` first if
  `docker ps` shows it not running.

## Training on synthetic + your own labeled data

`src/train.py` accepts an optional CSV path argument, so you can train on any
file with the same schema instead of only `config.TRAINING_DATA_PATH`:

```bash
uv run python -m src.train [path/to/data.csv]   # defaults to config.TRAINING_DATA_PATH
```

To train on the synthetic data *plus* your own labeled data (rather than
replacing one with the other), combine them into one CSV first, then point
training at the combined file.

### 1. Drop your CSV in `data/raw/`

Your file must have the same columns as the synthetic data: `date,
description, amount, category, subcategory`. `category` and `subcategory`
values should match the taxonomy in `src/taxonomy.py` exactly (case- and
punctuation-sensitive) — rows with a blank category/subcategory are dropped
automatically by `drop_unlabeled()`, but rows with a *misspelled* category
are not caught there.

```bash
cp /path/to/your/transactions.csv data/raw/transactions.csv
```

`data/raw/*.csv` is gitignored, so this file never gets committed.

### 2. Combine it with the synthetic dataset

```bash
uv run python -c "
import pandas as pd
from src import config

synthetic = pd.read_csv(config.SYNTHETIC_DATA_PATH)
real = pd.read_csv(config.RAW_DATA_PATH)

expected_cols = ['date', 'description', 'amount', 'category', 'subcategory']
assert list(synthetic.columns) == expected_cols
assert list(real.columns) == expected_cols, f'expected {expected_cols}, got {list(real.columns)}'

combined = pd.concat([synthetic, real], ignore_index=True)
out_path = config.DATA_DIR / 'combined' / 'combined_transactions.csv'
out_path.parent.mkdir(parents=True, exist_ok=True)
combined.to_csv(out_path, index=False)
print(f'Wrote {len(combined)} rows ({len(synthetic)} synthetic + {len(real)} real) to {out_path}')
"
```

`data/combined/*.csv` is also gitignored, since it's a generated artifact
that may contain your real transaction data.

Before training, it's worth sanity-checking that your categories/subcategories
actually match the taxonomy, so a typo doesn't silently get dropped or cause
a hard failure during training:

```bash
uv run python -c "
import pandas as pd
from src import config, taxonomy

real = pd.read_csv(config.RAW_DATA_PATH)
bad_categories = set(real['category'].dropna()) - set(taxonomy.CATEGORIES.keys()) - {''}
print('Unknown categories:', bad_categories or 'none')

all_subcats = {s for subs in taxonomy.CATEGORIES.values() for s in subs}
bad_subcats = set(real['subcategory'].dropna()) - all_subcats - {''}
print('Unknown subcategories:', bad_subcats or 'none')
"
```

If either set is non-empty, fix those rows in your source CSV (typo, wrong
casing, or a subcategory nested under the wrong category) and re-run step 2.

### 3. Train on the combined file

```bash
uv run python -m src.train data/combined/combined_transactions.csv
```

This runs the exact same pipeline as M4 (drop report, stratified split, fit
preprocessor once, train category + subcategory models) but on the combined
data, and overwrites the artifacts under `models/`. `models/metadata.json`
records the path actually used (`training_data_path`) so you can confirm
which dataset produced a given set of artifacts.

### 4. Re-verify

Re-run the M5 and M7 checks above (`predict_cli`, `/health`, `/predict`) to
confirm predictions still look sane, and compare `models/metrics/*.json`
against the synthetic-only run to see whether your real data changed
per-class precision/recall — a large drop in a category you added real data
for likely means that category needs more labeled rows, not a code change.

If your real dataset by itself is large enough to be useful (rather than a
few sample rows for gap-filling), you can also train on it exclusively —
without combining — to compare:

```bash
uv run python -m src.train data/raw/transactions.csv
```

### Notes on combining datasets

- Order in the `pd.concat` doesn't matter for training (the split is
  stratified/shuffled by `train_test_split`), but if you rerun step 2 whenever
  you add more real rows, keep regenerating `data/combined/combined_transactions.csv`
  from scratch rather than appending — it keeps "recreate from sources" as the
  one mental model instead of two.
- If your real data has very few rows for a given subcategory (fewer than 2
  in the combined category|subcategory split), `_stratified_split` in
  `src/train.py` will warn and fall back to a non-stratified split for the
  whole dataset — check the training output for that warning.
- Categories with too few *training* rows for a given subcategory (< 2
  distinct subcategories, or 0 rows) are skipped for that category's
  subcategory model and reported in `metadata.json`'s `skipped_categories` —
  this can happen if your real data only covers subcategories the synthetic
  generator already covers well, which is fine, or if a whole category has no
  data at all, which is worth noticing.

## Notes

- `models/` and `data/raw/*.csv` are gitignored — `models/` is entirely
  regenerated by `uv run python -m src.train`.
- `src/train.py` sets `RANDOM_SEED = 42` (in `src/config.py`) for
  reproducible splits and model fits.
- If you see `ConvergenceWarning` during training it's suppressed
  intentionally in `train.py`; if accuracy looks off, consider raising
  `LogisticRegression(max_iter=...)`.
